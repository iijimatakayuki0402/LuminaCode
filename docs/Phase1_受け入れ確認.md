## 実装時に判明したこと（設計への反映）

- **思考ブロックは会話に結び付く**：完了した応答は API の内容ブロックをそのまま保存して送り返す。履歴の不整合は `prefix_mismatch_behavior: "drop_block"` で捨てて続行する（新しいアカウントでは既定でエラーになるため）。
- **Agent SDK の使用量は累計**：再開・分岐したセッションの累計は、元のセッション全体の値から続く（実 API で確認）。実行ごとの累計を保存し、スレッドで最後に実行した回の累計との差分を使用量とする。
- **safeStorage の鍵**：API キーの暗号化に使う鍵はデータ保存先の `Local State` にある。`api-key.bin` だけを移しても復号できない（バックアップ・復元の実装時に注意）。
- **Git Bash がある環境**：Agent SDK のコマンド実行は Bash になり、PowerShell のコマンドは失敗する（Claude は Bash のコマンドに切り替える）。

## Phase 1 の範囲で未対応・制限のある点

| 項目 | 内容 |
|---|---|
| 長い会話の仮想スクロール（10.1【推奨】） | 未対応。数千件規模のメッセージで描画が重くなる可能性がある |
| 回答拒否時の自動フォールバック | 未対応。拒否された旨を表示する。必要なら API の server-side fallbacks を追加できる（→ Phase 4 で CHT-16 として対応） |
| 通常チャットの生成中の上限到達 | 1 回のリクエストの途中では止めない（次のリクエストから停止）。Cowork は SDK の予算上限で中断する（ターン単位のため厳密ではない） |
| Cowork のサブエージェントの入れ子表示（6.6） | ツール実行は一覧に表示されるが、入れ子にはしていない |
| Web 検索・Web 取得のオン／オフ（6.6） | 常にオフ（既定の扱い）。切り替えの UI は未実装 |
| 優先度 S・C の項目 | Phase 2 以降（分岐の切り替え、拡張思考の設定、コンテキスト管理、検索、エクスポート、ファイルツリー、トースト通知、MCP・スキル・スラッシュコマンドの設定など） |
