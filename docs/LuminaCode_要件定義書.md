## 1. 目的と背景

Claude API 専用の、個人用ローカルチャットアプリ「Lumina Code」を構築する。

- プロジェクト単位で会話・設定を管理する。
- プロジェクト種別は「通常チャット」と「Cowork」の2種類とする。
  - 通常チャット：ファイルを参照しながら会話する。
  - Cowork：指定フォルダ内のファイルを Claude が読み書き・削除し、Claude Code 相当の機能で作業を進める。

## 2. スコープ

### 2.1 対象範囲（初期リリース）

- ダッシュボード、プロジェクト管理、通常チャット、Cowork、設定、API キー管理、使用量管理、安全機能
- Windows 向けのデスクトップアプリ

### 2.2 対象外

| 項目 | 理由 |
|---|---|
| 音声入力・音声読み上げ | Windows 標準の音声入力（Win+H）で代用できるため（要望書 7.6） |
| Claude API 以外のモデル・サービスの利用 | 要望（Claude API 専用） |
| 複数ユーザー、ログイン、クラウド同期 | 個人用ローカルアプリのため |
| macOS／Linux 対応 | 【推奨】初期は Windows のみ。技術選定上は将来の拡張が可能 |
| Claude Code の GUI 不向き機能（詳細は 6.6 の対応表） | 要望（アプリで実装できない機能は除く） |

## 3. 前提・制約

| ID | 内容 |
|---|---|
| CON-01 | 利用できる AI は Claude API のみ。API キー未設定ではチャット・Cowork を利用できない（要望）。 |
| CON-02 | 個人用の単一ユーザー利用。アプリ独自の認証は設けない。 |
| CON-03 | データはすべてローカルに保存する。外部に送信するのは Anthropic API への通信のみ。 |
| CON-04 | Cowork の操作範囲は、プロジェクトに設定したフォルダ（1つ）の内部に限る（要望）。 |
| CON-05 | 【推奨】動作環境は Windows 10 / 11（64bit）。インターネット接続が必要。 |

## 4. 用語

| 用語 | 定義 |
|---|---|
| プロジェクト | 会話・設定をまとめる最上位の単位。種別を持つ。 |
| 通常チャット | ファイル添付に対応した、一般的なチャット形式のプロジェクト種別。 |
| Cowork | 指定フォルダ内でファイル操作・コマンド実行などを Claude が自律的に行うプロジェクト種別。 |
| スレッド | プロジェクト内の1つの会話。1プロジェクトに複数持てる。 |
| カスタム指示 | プロジェクトごとに設定する、Claude へのシステムプロンプト相当の指示。 |
| 作業フォルダ | Cowork で Claude にフルアクセスを許可するフォルダ。 |

## 5. システム方針（【推奨】）

### 5.1 アプリ形態と技術構成

| 項目 | 推奨内容 | 理由 |
|---|---|---|
| 形態 | Windows デスクトップアプリ（Electron） | ファイル／フォルダ選択、OS 連携（暗号化保存、トースト通知）を素直に扱える。 |
| UI | React + TypeScript | 一般的で資料が多く、チャット UI の部品が豊富。 |
| 通常チャットの API 連携 | Anthropic 公式 SDK（TypeScript）で Messages API を利用 | ストリーミング、ファイル入力、プロンプトキャッシュ、拡張思考に対応。 |
| Cowork の実現方式 | **Claude Agent SDK（TypeScript）を採用** | Claude Code の機能（ツール、権限、サブエージェント、MCP、スキル、フック、`CLAUDE.md` など）を自前実装せずに利用でき、要望の「Claude Code の機能を可能な限り利用」に最も近い。 |
| データ保存 | SQLite（メタデータ・会話）＋ファイル（添付） | 検索、集計、エクスポートが容易。 |
| 秘密情報の保管 | Electron `safeStorage`（Windows では DPAPI を使用） | 平文で保存しないという要件を低コストで満たせる。 |

> **Phase 0 の検証結果（2026-10-02、詳細は `03.開発環境\docs\Phase0_技術検証結果.md`）**
> - Agent SDK には Windows 用の `claude.exe`（約 245MB）が同梱されるため、別途 Claude Code のインストールは不要。インストーラのサイズは約 205MB になる。
> - Git for Windows が無い環境でも、PowerShell ツールでコマンド実行ができた。Git は必須ではない。
> - Electron のメインプロセス上で動作し、`canUseTool` による許可／拒否、予算・ターン上限、中断が利用できる。
> - `canUseTool` は読み取り専用のコマンドでは呼ばれない。「すべて確認」を保証するため、権限ルールやフックとの併用が必要（Phase 1 で検証）。
> - 作業フォルダ境界の判定処理（シンボリックリンク・ジャンクション・8.3 短縮名対応）を実装・検証済み。

### 5.2 プロセス構成（概要）

- メインプロセス：ファイル I/O、DB、API キー、Agent SDK の実行、安全機能（パス検証、削除制御）
- レンダラー：UI のみ。ファイルや API キーには直接触れず、IPC 経由でメインに依頼する。

### 5.3 データ保存先

| データ | 保存先（【推奨】） |
|---|---|
| アプリ設定・DB | `%APPDATA%\LuminaCode\` 配下（`lumina.db` など） |
| 通常チャットの添付ファイル | `%APPDATA%\LuminaCode\attachments\<プロジェクトID>\` |
| API キー | `%APPDATA%\LuminaCode\` 配下に `safeStorage` で暗号化して保存 |
| 操作ログ・使用量ログ | DB 内（エクスポート可能） |
| Cowork の削除退避先 | 作業フォルダ直下の `.lumina-trash\`（9.2 参照） |
| Cowork の変更スナップショット | `%APPDATA%\LuminaCode\snapshots\<プロジェクトID>\`（作業フォルダ内を汚さないため） |

| CHT-14 | **直近に送信した指示（最新のユーザーメッセージ）を編集し、再送信できる**（下記の動作を参照）。 | M | 要望 |

**CHT-14 の動作（【推奨】）**

- 編集できるのは、スレッド内の**最新のユーザーメッセージ**とする。それより前のメッセージの編集・分岐は CHT-06（S）で扱う。
- 最新のユーザーメッセージに「編集」ボタンを表示する。押すと、その場で入力欄に切り替わり、「再送信」「キャンセル」を選べる。
- 再送信すると、その指示に対する既存の回答を破棄（旧版は分岐履歴として保持）し、編集後の内容で新しい回答を生成する。添付ファイルの追加・削除も編集できる。
- 生成中は編集できない（先に停止する）。
- **Cowork での注意**：再送信しても、前の実行で行われたファイル変更は自動では元に戻らない。再送信前に、「前回の変更を元に戻しますか？」と確認する（元に戻す／そのまま再送信／キャンセル）。
- 使用量は、再送信ぶんも加算する。

### 6.6 Claude Code 機能の対応表（【推奨】）

要望書の「アプリで実装できない機能の線引き」について、以下を初期案とする。設計時に Agent SDK の最新仕様で再確認すること。

| Claude Code の機能 | 対応方針 | 備考 |
|---|---|---|
| ファイル読み取り・書き込み・編集・検索（Read／Write／Edit／Glob／Grep） | **対応** | Cowork の中核。パス検証を必ず経由する。 |
| コマンド実行（Bash／PowerShell 系） | **対応（制限付き）** | 9.3 の方針に従う。 |
| Web 検索・Web 取得 | 対応（設定でオン／オフ、既定オフ） | 情報漏えいの観点から既定はオフ。 |
| 計画モード（Plan） | **対応** | 権限モードの1つとして提供（6.7）。 |
| 権限モード・許可／拒否ルール | **対応** | 6.7、9 章。 |
| todo 表示 | **対応** | COW-13。 |
| サブエージェント | **対応** | 進捗を UI に入れ子で表示。 |
| `CLAUDE.md` の読み込み | **対応** | COW-11。 |
| スキル（Skills） | 対応（作業フォルダ内の `.claude\skills` など、プロジェクト範囲のみ） | ユーザー全体のスキルは読み込まない【推奨】。 |
| スラッシュコマンド（カスタムコマンド） | 対応（入力欄で `/` 候補を表示） | 組み込みの `/help`、`/login` など CLI 操作専用のものは除外。 |
| MCP サーバー | 対応（プロジェクト単位で設定） | 設定 UI は S。追加時は信頼確認ダイアログを出す。 |
| フック（Hooks） | 対応（プロジェクト設定ファイルから） | 任意コマンド実行になるため、追加時に確認する。 |
| セッション再開・履歴 | 対応 | スレッドの履歴として保持。 |
| 対話型の端末 UI（TUI）、ステータスライン、キーバインド設定、ターミナル固有のセットアップ | **非対応** | 端末専用機能のため。 |
| CLI のログイン／アカウント切替（`/login`、`/logout`） | **非対応** | API キー方式に統一。 |
| IDE 連携、ブラウザ拡張連携、GitHub Actions 連携など外部ツール統合 | 非対応（将来検討） | |
| バックグラウンドタスク・スケジュール実行 | 非対応（将来検討） | アプリ終了時の扱いが複雑になるため。 |

### 6.7 権限モード（【推奨】）

| モード | 動作 | 既定 |
|---|---|---|
| 毎回確認 | 書き込み・削除・コマンド実行の都度、確認ダイアログを出す。読み取りは自動許可。 | ★既定 |
| 編集を自動許可 | ファイルの作成・編集は自動許可。削除とコマンド実行は確認する。 | |
| 計画のみ | 読み取りのみで計画を立案する。変更は一切行わない。 | |

- 削除は、どのモードでも**自動許可にはしない**（「常に許可」を明示設定した場合のみ例外）。
- 確認ダイアログの選択肢は「今回だけ許可」「このスレッドでは常に許可」「拒否」とする。「常に許可」はスレッドまたはプロジェクト単位で、設定画面から解除できる。
- 要望の「毎回確認」「常に許可」「今回は許可」(追加 2)をこの構成で満たす。

### 6.14 エラー処理

| 事象 | 動作 |
|---|---|
| レート制限（429）・一時的な過負荷（529、5xx） | 指数バックオフで最大 3 回まで自動リトライ。待機中はその旨を表示する。 |
| 認証エラー（401／403） | API キーの再設定を促す。 |
| 残高不足・請求関連エラー | 内容を分かりやすく表示し、Anthropic のコンソールを確認するよう案内する。 |
| オフライン | 「オフラインです」と表示し、送信をブロックする。履歴の閲覧、検索、エクスポートは利用可能とする。 |
| 入力過大（コンテキスト超過・ファイル過大） | 原因と対処（圧縮、ファイル削減）を表示する。 |
| アプリ異常終了 | 再起動後、未完了の応答／Cowork 実行の状態を「中断」として表示し、途中までの内容を保持する。 |

エラー内容は、API キーやファイル内容を含めずに、ローカルのログファイルに記録する。

| ID | 要件 |

**システムチックなデザイン指針（【推奨】）**

- ダークモードは、黒に近い濃紺／グレー（例：`#0E1116`）を基調とし、アクセントカラーは細い枠線、選択状態、ボタン、送信中のインジケーターなどに絞って使う。
- フォントは、UI に視認性の高いサンセリフ、コード・ログ・ツール実行表示に等幅フォントを使う（日本語は Yu Gothic UI／Meiryo UI など、等幅は Cascadia Code／Consolas などの Windows 標準フォントを基本とし、フォントの同梱はしない）。
- 角丸は小さめ（2〜4px）、細い罫線、情報を詰めすぎない余白で、整然とした印象にする。
- メッセージ表示は、吹き出しではなく、ロール名（USER／CLAUDE）とタイムスタンプを付けた「ログ行」風のレイアウトにする。Cowork のツール実行は、ターミナル風のブロックで表示する。
- 生成中は、カーソルの点滅や細い進捗ラインなど、控えめなアニメーションで状態を示す（OS の「視覚効果を減らす」設定ではアニメーションを無効にする）。
- 状態表示（モデル名、トークン数、コンテキスト使用率、概算コスト）は、ステータスバー風に画面下部または上部へ常時表示する。
- **プロジェクト種別の色との関係**：種別色は、アクセントカラーごとに下表の2色を割り当てる。種別バッジ・カードの帯にのみ使い、アクセントカラーそのものとは使い分ける。

**種別色（【推奨】、デザイン時に調整）**

| アクセントカラー | 通常チャット（ライト／ダーク） | Cowork（ライト／ダーク） | 配色の考え方 |
|---|---|---|---|
| 薄紫 | ティール `#2FA89A`／`#5CD3C4` | アンバー `#E0963C`／`#F2BC6A` | 紫に対し、青緑と琥珀を組み合わせた、はっきり区別できる3色 |
| 水色 | インディゴ紫 `#7C6FD9`／`#A89CF0` | アンバー `#DE9A2E`／`#F4C062` | 水色と近い色相の紫でまとめ、補色寄りの琥珀を Cowork に充てる |
| 薄い赤 | スレートブルー `#4F8FD6`／`#86B8F0` | ゴールド `#CDA02B`／`#EBCB62` | 赤に対し、寒色の青と暖色の黄金で、赤と混ざらない2色 |

- 種別色と選択中のアクセントカラーは、同じ色相にならないようにする（アクセントカラーの変更で、種別の判別が難しくならないこと）。
- 色覚多様性への配慮として、種別はアイコンとラベルでも必ず識別できるようにする（DSH-04）。

## 14. 受け入れ基準（主要なもの）

1. API キー未設定の状態では、チャットと Cowork を開始できず、設定画面へ誘導される。
2. 無効な API キーは疎通テストで拒否され、保存されない。保存された API キーは、設定ファイルやログ内に平文で存在しない。
3. プロジェクト名が空、または Cowork で作業フォルダが未指定の場合、作成できない。
4. ダッシュボードで、通常チャットとCowork が色・アイコン・ラベルで区別できる。
5. 通常チャットで、ファイルを添付した会話と、添付なしの会話が成立する。生成を途中で停止できる。
6. Cowork で、作業フォルダ内のファイルの作成・編集・削除を、チャットで指示して実行できる。
7. `..` やシンボリックリンク／ジャンクションを使った、作業フォルダ外へのファイル操作が拒否される。
8. 削除指示では確認ダイアログが出る。許可後のファイルは `.lumina-trash` に退避され、画面から復元できる。
9. Cowork の実行中にいつでも中断でき、ファイル変更をまとめて元に戻せる。
10. 月額／プロジェクト上限を超えると、警告後に新規リクエストが停止される。
11. モデルを全体・プロジェクト・スレッドの各階層で選択でき、現在のモデルが画面に表示される。
12. 操作ログに、Cowork のすべてのツール実行が記録され、画面から閲覧できる。
13. 設定で、アクセントカラー（薄紫／水色／薄い赤）と表示モード（ダーク／ライト／標準）を選べ、再起動なしで反映される。再起動後も設定が保持される。
14. 3色×3モードのすべての組み合わせで、文字が読め、画面が崩れない。
15. 回答の下にコピーボタンがあり、押すと回答全文がクリップボードにコピーされる。
16. 最新のユーザーメッセージを編集して再送信でき、新しい回答が生成される。Cowork では、再送信前に前回の変更を元に戻すか確認される。
